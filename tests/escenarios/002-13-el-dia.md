# 002-13 · El día uno y las dos semanas siguientes

> **Principio:** [P1 (texto operable a mano)](../../docs/principios.md#L9), [P2 (organización emergente)](../../docs/principios.md#L17), [P4 (determinismo)](../../docs/principios.md#L33), [P6 (conjunto canónico)](../../docs/principios.md#L55), [P9 (reconstrucción)](../../docs/principios.md#L79) · **Brief:** [Triangulación tiempo × compromiso](../../docs/brief.md#L27) · **Spec:** [`spec/tuku.md`](../../spec/tuku.md) · **Libro:** [Registro, Pendiente, AHORA.md y las bitácoras](../../template/vanilla/LIBRO-DE-ESTILO.md)

El martes 11 de agosto con un comando por hecho y el reloj inyectado (`TUKU_NOW`), y después los lunes 17 y 24: `AHORA.md` crece, ordena sus días del más nuevo al más viejo y archiva solo. Cada escenario parte del vault que dejó el anterior.

## Escenario: los registros del martes caen en su día, el más reciente arriba

Dado un vault recién sembrado
```bash
tuku init mi-vault
cd mi-vault
```
Cuando se registran cinco hechos, el último con una hora anterior a la del reloj
```bash
TUKU_NOW="2026-08-11 09:12" tuku entry create --body "**señal**: la administradora responde los mensajes con varios días de atraso"
TUKU_NOW="2026-08-11 11:30" tuku entry create --body "hice la consulta presencial por el standing desk"
TUKU_NOW="2026-08-11 12:05" tuku entry create --body "**cachureo**: ordené los cables del escritorio"
TUKU_NOW="2026-08-11 18:40" tuku entry create --body "le mandé la boleta de gastos comunes del depto centro a la administradora por WhatsApp"
TUKU_NOW="2026-08-11 18:50" tuku entry create --at "2026-08-11 10:00" --body "**progreso**: respondí el correo del contador"
TUKU_NOW="2026-08-11 18:55" tuku doctor entry
```
Entonces `AHORA.md` tiene un solo día, `## Martes 11 de agosto`, bajo el foco
Y sus registros van de la hora más reciente a la más antigua: 18:40, 12:05, 11:30, 10:00 y 09:12
Y el diff toca solo `AHORA.md` y `ambitos/personal/personal.md`
Y `tuku doctor entry` sale con código 0 y pregunta por `**cachureo**`, que no está en el vocabulario

## Escenario: los pendientes nacen con su Creado y entran a la ventana

Dado el vault con los registros del martes
```bash
cp -r ../los-registros-del-martes-caen/mi-vault .
cd mi-vault
```
Cuando se abren cinco pendientes: dos sin fecha, uno de la semana siguiente, uno que vence en dos días y otro que vence en veinte
```bash
TUKU_NOW="2026-08-11 13:00" tuku todo open --body "comprar una maleta"
TUKU_NOW="2026-08-11 13:05" tuku todo open --horizon "próxima semana" --body "renovar el seguro del local"
TUKU_NOW="2026-08-11 13:10" tuku todo open --due 2026-08-13 --body "llamar al contador"
TUKU_NOW="2026-08-11 13:15" tuku todo open --due 2026-08-31 --body "pagar la patente"
TUKU_NOW="2026-08-11 13:20" tuku todo open --body "avisar de los GGCC a la administradora"
```
Entonces cada fila de `PENDIENTES.md` lleva `Creado` 2026-08-11
Y el bloque `Pendientes de los próximos 7 días` de `AHORA.md` lista los dos sin fecha y el que vence el 13, y no el de la semana siguiente ni el de veinte días
Y el jueves 13 existe en `AHORA.md` con su callout `Pendientes del día`
Y `ambitos/PENDIENTES-AMBITOS.md` los lista todos bajo `personal`

## Escenario: cerrar un pendiente el mismo día deja solo el cierre

Dado el vault con los cinco pendientes abiertos
```bash
cp -r ../los-pendientes-nacen-con-su/mi-vault .
cd mi-vault
```
Cuando se cierra uno esa misma tarde
```bash
TUKU_NOW="2026-08-11 19:05" tuku todo close "avisar de los GGCC a la administradora"
TUKU_NOW="2026-08-11 19:06" tuku doctor todo
```
Entonces la fila sale de `PENDIENTES.md` y del bloque de la ventana
Y el martes 11 tiene el cierre `(Hecho): ~~avisar de los GGCC a la administradora~~` y ya no la apertura de las 13:20
Y `tuku doctor todo` sale limpio

## Escenario: un ámbito con su jerarquía

Dado el vault al caer la tarde
```bash
cp -r ../cerrar-un-pendiente-el-mismo/mi-vault .
cd mi-vault
```
Cuando se crea un ámbito y, dentro de él, otro
```bash
TUKU_NOW="2026-08-11 19:30" tuku scope create depto-centro
TUKU_NOW="2026-08-11 19:35" tuku scope create gastos --parent depto-centro
TUKU_NOW="2026-08-11 19:40" tuku doctor scope
```
Entonces existen `ambitos/depto-centro/depto-centro.md` y `ambitos/depto-centro/gastos/gastos.md`, cada página con su transclusión de pendientes
Y el registro de las 18:40, que menciona el depto, sigue como lo escribió el autor: crear el ámbito solo agrega las dos constancias
Y el martes 11 tiene `**nota**: abrí el ámbito` de `depto-centro` y de `gastos`, este último `bajo` su padre
Y `tuku doctor scope` sale limpio

## Escenario: una nota enlazada a su ámbito

Dado el vault con `depto-centro` y `notas/` vacío
```bash
cp -r ../un-ambito-con-su-jerarquia/mi-vault .
cp ../../tests/escenarios/fixtures/002-13-el-dia/cuerpo-nota.md .
cd mi-vault
```
Cuando se crea la nota
```bash
TUKU_NOW="2026-08-11 21:15" tuku note create "cómo funciona el cobro de gastos comunes en una copropiedad" --body-file ../cuerpo-nota.md --scope depto-centro
TUKU_NOW="2026-08-11 21:20" tuku doctor note notas/como-funciona-el-cobro-de-gastos-comunes-en-una-copropiedad.md
```
Entonces existe `notas/como-funciona-el-cobro-de-gastos-comunes-en-una-copropiedad.md` con `type: Note`, `created: 2026-08-11`, el cuerpo del fixture y un enlace a `depto-centro`
Y el martes 11 gana la constancia que enlaza a la nota, y la página de `depto-centro` la recibe
Y la nota pasa el lint

## Escenario: el foco es del autor y tuku lo conserva

Dado el vault al cierre del martes
```bash
cp -r ../una-nota-enlazada-a-su-ambito/mi-vault .
cd mi-vault
```
Cuando el autor escribe su foco con un editor y registra un hecho más
```bash
sed -i.bak 's/^> Escribe aquí en qué concentrarte estos días\./> Cerrar la semana sin deuda con la administración./' AHORA.md && rm AHORA.md.bak
TUKU_NOW="2026-08-11 21:40" tuku entry create --body "**progreso**: dejé lista la lista de la semana"
```
Entonces el foco queda como lo escribió el autor, sobre el bloque de pendientes
Y el registro de las 21:40 queda el primero del martes

## Escenario: el lunes 17 todavía no archiva nada

Dado el vault del martes con su foco
```bash
cp -r ../el-foco-es-del-autor-y-tuku-lo/mi-vault .
cd mi-vault
```
Cuando se registra el lunes siguiente por la mañana
```bash
TUKU_NOW="2026-08-17 09:00" tuku entry create --body "**progreso**: retomé la semana con la lista del martes"
TUKU_NOW="2026-08-17 09:05" tuku doctor
```
Entonces `AHORA.md` ordena sus días del más nuevo al más viejo: lunes 17, jueves 13 y martes 11
Y `bitacoras/` no existe
Y `comprar una maleta`, que se prometió el 11 como `esta semana`, sigue sin estar atrasada
Y `tuku doctor` dice que el vault está sano

## Escenario: el lunes 24 archiva la semana que salió de la ventana

Dado el vault con el lunes 17 registrado
```bash
cp -r ../el-lunes-17-todavia-no-archiva/mi-vault .
cd mi-vault
```
Cuando se escribe el lunes de dos semanas después
```bash
TUKU_NOW="2026-08-24 08:30" tuku entry create --body "**progreso**: abrí la semana del 24"
TUKU_NOW="2026-08-24 08:35" tuku doctor
```
Entonces nace `bitacoras/bitacora-20260810-20260816.md` con `from: 2026-08-10` y `to: 2026-08-16`
Y la bitácora lleva los registros del martes 11 en el mismo orden, con los links de su ruta desde `bitacoras/`
Y `AHORA.md` conserva el foco y los días 24 y 17, y ya no el jueves 13 ni el martes 11
Y los pendientes que la semana archivada dejó sin cerrar siguen en `PENDIENTES.md`, ahora marcados como atrasados en la ventana
Y `tuku doctor` dice que el vault está sano

## Escenario: un registro de fecha antigua va a su bitácora

Dado el vault con la primera bitácora semanal
```bash
cp -r ../el-lunes-24-archiva-la-semana/mi-vault .
cd mi-vault
```
Cuando se registran dos hechos que ocurrieron antes, uno en la semana ya archivada y otro dos semanas antes
```bash
TUKU_NOW="2026-08-24 09:00" tuku entry create --at "2026-08-12 10:00" --body "**señal**: el contador confirmó el plazo del miércoles"
TUKU_NOW="2026-08-24 09:05" tuku entry create --at "2026-07-29 16:30" --body "**progreso**: cerré el contrato con el contador"
```
Entonces el primero queda en `bitacora-20260810-20260816.md`, bajo el miércoles 12
Y el segundo crea `bitacora-20260727-20260802.md`, con `from: 2026-07-27` y `to: 2026-08-02`
Y `AHORA.md` no cambia

## Escenario: repetir el día no cambia nada

Dado el vault con dos bitácoras
```bash
cp -r ../un-registro-de-fecha-antigua/mi-vault .
cd mi-vault
```
Cuando se repiten los comandos que escriben y se regenera lo derivado
```bash
TUKU_NOW="2026-08-24 08:30" tuku entry create --body "**progreso**: abrí la semana del 24"
TUKU_NOW="2026-08-24 09:00" tuku entry create --at "2026-08-12 10:00" --body "**señal**: el contador confirmó el plazo del miércoles"
TUKU_NOW="2026-08-24 09:05" tuku entry create --at "2026-07-29 16:30" --body "**progreso**: cerré el contrato con el contador"
TUKU_NOW="2026-08-24 09:10" tuku regenerate
```
Entonces el diff del vault es vacío
Y `tuku regenerate` dice que todo estaba al día
Y `tuku doctor` dice que el vault está sano
```bash
TUKU_NOW="2026-08-24 09:15" tuku doctor
```

## Aceptación humana (en Obsidian)

- `AHORA.md` se lee de arriba abajo: foco, pendientes de la semana y los días del más nuevo al más viejo.
- El martes 11 se lee entero sin la conversación que lo originó; el registro sin clasificación se lee tan completo como los clasificados.
- La bitácora `bitacora-20260810-20260816.md` conserva el martes 11 tal como estaba y sus links abren.
- El link a `depto-centro` abre su página, que muestra la transclusión de sus pendientes y su actividad.
