# 002-13 · El día uno

> **Principio:** [P1 (texto operable a mano)](../../docs/principios.md#L9), [P2 (organización emergente)](../../docs/principios.md#L17), [P4 (determinismo)](../../docs/principios.md#L33), [P6 (conjunto canónico)](../../docs/principios.md#L55), [P9 (reconstrucción)](../../docs/principios.md#L79) · **Brief:** [Triangulación tiempo × compromiso](../../docs/brief.md#L27) · **Spec:** [`spec/ciclo.md`](../../spec/ciclo.md), [`spec/bitacora.md`](../../spec/bitacora.md), [`spec/pendientes.md`](../../spec/pendientes.md), [`spec/ambitos.md`](../../spec/ambitos.md), [`spec/notas.md`](../../spec/notas.md)

El martes 11 de agosto entero, hora por hora, con un comando por hecho: el mismo día que el [`003-10`](003-10-el-dia-uno-en-un-turno.md) dicta. Cada escenario parte del vault que dejó el anterior.

## Escenario: la semana abre con el vault

Dado un vault recién sembrado
```bash
tuku init mi-vault --at 2026-08-11
cd mi-vault
```
Cuando se pide el ciclo del martes 11
```bash
tuku process cycle --at 2026-08-11
```
Entonces el comando informa que `AHORA.md` ya cubre la fecha y no escribe nada
Y `AHORA.md` tiene `from: 2026-08-10`, `to: 2026-08-16` y la semana de lunes a domingo, de `## Lunes 10 de agosto` a `## Domingo 16 de agosto`
Y ningún placeholder (`AAAA-MM-DD`, `DD de mes`) sobrevive fuera de bloques de código

## Escenario: los registros caen en su día y en orden

Dado el vault con la semana abierta
```bash
cp -r ../la-semana-abre-con-el-vault/mi-vault .
cd mi-vault
```
Cuando se registran cuatro hechos en desorden y se revisa la bitácora
```bash
tuku entry create --at "2026-08-11 18:40" --body "le mandé la boleta de gastos comunes del depto centro a la administradora por WhatsApp"
tuku entry create --at "2026-08-11 09:12" --body "**señal**: la administradora responde los mensajes con varios días de atraso"
tuku entry create --at "2026-08-11 12:05" --body "**cachureo**: ordené los cables del escritorio"
tuku entry create --at "2026-08-11 11:30" --body "hice la consulta presencial por el standing desk"
tuku doctor entry
```
Entonces los cuatro quedan bajo `## Martes 11 de agosto`, ordenados por hora: 09:12, 11:30, 12:05 y 18:40
Y los demás días siguen vacíos
Y la página de `personal` los recibe bajo `## Esta semana`, sin hora ni ámbito
Y el diff toca solo `AHORA.md` y `ambitos/personal/personal.md`
Y `tuku doctor entry` sale con código 0 y pregunta por `**cachureo**`, que no está en el vocabulario

## Escenario: abrir los pendientes de hoy

Dado el vault con los registros de la mañana
```bash
cp -r ../los-registros-caen-en-su-dia-y/mi-vault .
cd mi-vault
```
Cuando se abren dos pendientes
```bash
tuku todo open --at "2026-08-11 13:00" --body "comprar una maleta"
tuku todo open --at "2026-08-11 14:20" --body "avisar de los GGCC a la administradora"
```
Entonces `PENDIENTES.md` gana dos filas en `esta semana`, sin fecha y con el cuerpo literal:
`| esta semana |  | [personal](ambitos/personal/personal.md) | avisar de los GGCC a la administradora |`
Y `AHORA.md` gana los dos registros `**pendiente**` en el martes 11
Y la página de `personal` y `ambitos/PENDIENTES-AMBITOS.md` los reciben

## Escenario: cerrarlos el mismo día deja solo el cierre

Dado los dos pendientes abiertos el martes 11
```bash
cp -r ../abrir-los-pendientes-de-hoy/mi-vault .
cd mi-vault
```
Cuando se cierran esa misma tarde
```bash
tuku todo close --at "2026-08-11 19:05" "avisar de los GGCC a la administradora"
tuku todo close --at "2026-08-11 19:10" "comprar una maleta"
```
Entonces la tabla de `PENDIENTES.md` queda vacía, con su cabecera
Y el martes 11 tiene los dos cierres, `(Hecho): ~~cuerpo~~`, y ya no las aperturas de las 13:00 y las 14:20, ni en `AHORA.md` ni en la página de `personal`
Y `tuku doctor todo` sale limpio
```bash
tuku doctor todo
```

## Escenario: un frente nuevo se crea sin tocar lo ya escrito

Dado el vault con la mención `del depto centro` en el registro de las 18:40
```bash
cp -r ../cerrarlos-el-mismo-dia-deja/mi-vault .
cd mi-vault
```
Cuando se crea el ámbito
```bash
tuku scope create depto-centro --at "2026-08-11 18:45"
```
Entonces existe `ambitos/depto-centro/` con su página `depto-centro.md` y nada más
Y `depto-centro.md` transcluye `![[../PENDIENTES-AMBITOS.md#^depto-centro]]`, y `ambitos/PENDIENTES-AMBITOS.md` gana el bloque `^depto-centro`, con solo su título
Y la mención de las 18:40 sigue como la escribió el autor, sin link: `AHORA.md` solo gana la constancia
Y el martes 11 gana la constancia `- 18:45 - [depto-centro](ambitos/depto-centro/depto-centro.md) **nota**: abrí el ámbito`
Y `ambitos/personal/` no cambia

## Escenario: la nota del frente queda escrita y enlazada

Dado el vault con `depto-centro` y `notas/` vacío
```bash
cp -r ../un-frente-nuevo-se-crea-sin/mi-vault .
cp ../../tests/escenarios/fixtures/002-13-el-dia/cuerpo-nota.md .
cd mi-vault
```
Cuando se crea la nota
```bash
tuku note create "cómo funciona el cobro de gastos comunes en una copropiedad" --body-file ../cuerpo-nota.md --scope depto-centro --at "2026-08-11 21:15"
```
Entonces existe `notas/como-funciona-el-cobro-de-gastos-comunes-en-una-copropiedad.md` con `type: Note`, `created: 2026-08-11`, el cuerpo del fixture y un enlace a `depto-centro`
Y el martes 11 gana la constancia que enlaza a la nota, y la página de `depto-centro` la recibe bajo `## Esta semana`
Y la nota pasa el lint
```bash
tuku doctor note notas/como-funciona-el-cobro-de-gastos-comunes-en-una-copropiedad.md
```

## Escenario: los pendientes de mañana y pasado llegan a su día

Dado el vault al cierre del martes 11
```bash
cp -r ../la-nota-del-frente-queda/mi-vault .
cd mi-vault
```
Cuando a las 21:30 se abren cuatro pendientes que vencen el miércoles 12 y el jueves 13, en desorden
```bash
tuku todo open --at "2026-08-11 21:30" --due 2026-08-13 --body "comprar pasajes de tren"
tuku todo open --at "2026-08-11 21:31" --due "2026-08-12 09:00" --body "pagar la sesión con el psicólogo"
tuku todo open --at "2026-08-11 21:32" --due 2026-08-13 --body "llamar a la administradora"
tuku todo open --at "2026-08-11 21:33" --due 2026-08-12 --scope depto-centro --body "pagar los gastos comunes"
```
Entonces cada registro queda el martes 11, cuando se prometió, y cada fila de `PENDIENTES.md` queda `con fecha` con su día, y su hora si la tiene, en `Vence`, sin callouts ni anclas
Y cada día de `AHORA.md` recibe sus dos pendientes en su callout, con la hora si vencen a una hora:
```markdown
## Miércoles 12 de agosto
> [!todo] Pendientes del día
> - 09:00 - [personal](ambitos/personal/personal.md) - pagar la sesión con el psicólogo
> - [depto-centro](ambitos/depto-centro/depto-centro.md) - pagar los gastos comunes
```
Y el callout de cada ámbito en `ambitos/PENDIENTES-AMBITOS.md` los lista por fecha, con el `date_format` de `reglas/config.tuku.md` y sin el ámbito:
```markdown
> [!todo] Pendientes en **Personal** ^personal
> - Ago/12 09:00 - pagar la sesión con el psicólogo
> - Ago/13 - comprar pasajes de tren
> - Ago/13 - llamar a la administradora
```
Y `tuku doctor todo` sale limpio
```bash
tuku doctor todo
```

## Escenario: repetir el día no cambia nada

Dado el vault del día uno completo
```bash
cp -r ../los-pendientes-de-manana-y/mi-vault .
cp ../../tests/escenarios/fixtures/002-13-el-dia/cuerpo-nota.md .
cd mi-vault
```
Cuando se repite cada comando del día que no abre un pendiente ya cerrado, y se regenera lo derivado
```bash
tuku entry create --at "2026-08-11 18:40" --body "le mandé la boleta de gastos comunes del depto centro a la administradora por WhatsApp"
tuku entry create --at "2026-08-11 09:12" --body "**señal**: la administradora responde los mensajes con varios días de atraso"
tuku entry create --at "2026-08-11 12:05" --body "**cachureo**: ordené los cables del escritorio"
tuku entry create --at "2026-08-11 11:30" --body "hice la consulta presencial por el standing desk"
tuku todo close --at "2026-08-11 19:05" "avisar de los GGCC a la administradora"
tuku todo close --at "2026-08-11 19:10" "comprar una maleta"
tuku scope create depto-centro --at "2026-08-11 19:30"
tuku note create "cómo funciona el cobro de gastos comunes en una copropiedad" --body-file ../cuerpo-nota.md --scope depto-centro --at "2026-08-11 21:15"
tuku todo open --at "2026-08-11 21:30" --due 2026-08-13 --body "comprar pasajes de tren"
tuku todo open --at "2026-08-11 21:31" --due "2026-08-12 09:00" --body "pagar la sesión con el psicólogo"
tuku todo open --at "2026-08-11 21:32" --due 2026-08-13 --body "llamar a la administradora"
tuku todo open --at "2026-08-11 21:33" --due 2026-08-12 --scope depto-centro --body "pagar los gastos comunes"
tuku regenerate
```
Entonces el diff del vault es vacío
Y un cierre repetido se reporta sin pareja, y `tuku regenerate` dice que todo estaba al día
Y `tuku doctor` dice que el vault está sano
```bash
tuku doctor
```

## Aceptación humana (en Obsidian)

- El martes 11 se lee entero sin la conversación que lo originó; el registro sin clasificación se lee tan completo como los clasificados.
- Cada pendiente abierto y cerrado ese día se lee una sola vez, tachado.
- El link a `depto-centro` desde `AHORA.md` abre su página, y esa página muestra la transclusión de sus pendientes y la actividad sin marcas artificiales.
- En la nota, cada enlace de `## Ver además` dice en una frase para qué sirve.
- El miércoles 12 y el jueves 13 muestran su callout de pendientes antes del primer registro; la columna `Vence` de `PENDIENTES.md` tiene la fecha limpia.
